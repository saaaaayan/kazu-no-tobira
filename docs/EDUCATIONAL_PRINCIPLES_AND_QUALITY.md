# 数のトビラ｜教育理念・学習体験・教材品質の最上位仕様

> ユーザー提供「数のトビラ 開発引き継ぎ指示書｜2026年11月17日版｜教育理念・品質管理・開発方針」を基に正式な開発判断基準を整理したもの。全16島・試作版・β版・一般公開版に適用する。  
> **既存の最新確定仕様を勝手に上書きしない**。異なる時点の数値や旧名称が存在する場合は、[全島ステージ構成](STAGE_STRUCTURE_AND_NAMES.md)と[最上位問題制作計画](QUESTION_FACTORY_MASTER_PLAN.md)の後日確定事項を維持し、衝突内容を明示する。

## 1. 最上位設計原則【最重要】

> **子どもが、ひとりで学べる。**

親や先生が横にいなくても、子ども自身が操作し、問題に挑戦し、考え、理解し、次の学習へ進める。単に問題を解かせるのではなく、**自分で考える力・理解する力・学び続ける力**を育てる。

すべての機能と文言の設計・実装・レビュー・公開判断では、まず次を問う。

> **この機能は、子どもが自分の力で学習を進めることを助けるか？**

この理念はマップ・操作・問題・ヒント・解答・解説・復習・障害表示・課金区分にも及ぶ。ゲーム性と収益化を優先して自立学習を阻害しない。

## 2. 教材品質の4本柱

1. **問題**：数学的に正しく、該当ステージの単元・学年・前提知識と一致し、考える価値がある。
2. **ヒント**：答えを先に明かさず、子ども自身の発見を支える。必要に応じて3段階で情報を増やす。
3. **解答・採点**：正答・別解・許容表記・解答形式を検証し、見かけの正誤や曖昧な手書き認識だけで誤答としない。
4. **解説**：なぜそうなるのか、必要な前提から理解できるように、途中を飛ばさず伝える。

**数学的に正しい説明と、子どもが理解できる説明は別物である。**

数学的な検算は自動テスト・独立した手法・AI等で補助し、説明の教育的なわかりやすさは開発者のレビューと承認を必要とする。プログラム検証済みを教育審査済みと同一視しない。

### 問題・ヒント・解説の教育的レビュー観点

- 学年・時期に合う漢字、語彙、概念、既習事項になっているか。
- 未習漢字はひらがな・ふりがなを使い、読めないことが学習の障害にならないか。
- 文が長すぎないか、複数の条件が複雑すぎないか、曖昧な指示はないか。
- なぜその答えかを説明できるか。必要な途中の考え方を省略していないか。
- 図・数直線・具体物・グラフ・アニメーションがあった方が理解しやすくないか。
- ヒントが早く答えを露出していないか、誤答時に別の手がかりがあるか。
- 描画・操作の仕方（タップ・ドラッグ・書字）自体が難しすぎないか。
- 同じ技能を測る単なる数値差替えだけでなく、学習価値のあるバリエーションか。
- 設問・図・正答・採点条件・各ヒント・解説が**相互に矛盾しないか**。
- その問題を**このステージ**に置くことが適切か。学年・単元・難易度・前提技能が一致するか。

**不一致の実例**：開発プレビューで幼児「ものをかぞえる」に小1の足し算例題が表示された。問題の数合わせより、学習目標に合う出題を優先する（[Issue #66](https://github.com/saaaaayan/kazu-no-tobira/issues/66)）。ステージの学習目標に一致するサンプルが無い場合は無関係な計算問題を表示せず「準備中」とする。

## 3. 学年・発達段階別の日本語とUI

### 幼児・小学1〜3年生

- 学年と年度内の進度を意識し、**小学1年生の年度初めに年度末の漢字を前提にしない**。
- 未習漢字・難しい語彙を避ける。短文・具体例・適切な改行・大きな押しやすいボタンを優先する。
- 幼児向けの数や具体物は視線を追いやすい**横一列を原則**とする。上下・左右・前後の空間関係を学ぶ課題では必要な配置を使う。
- 読字を必須にしない。図・イラストと、必要に応じた音声読み上げ・操作の実演を検討する。
- 誤操作に寛容で、わからない操作をゲーム内で自分で確認・やり直しできるようにする。
- 手書き認識は認識失敗と数学的な誤答を区別する。手書きメモは利用でき、認識精度を理由に学習を止めない。

### 小学4〜6年生

習う数学用語を正確に使う。具体物から抽象へ移る際に説明の飛躍を作らず、必要な図・短い段階説明を用意する。

### 中学生・高校生・大学レベル

定義、条件、論理の厳密さ、途中式、別解、証明・反例を重視する。過剰に幼児化した文体にせず、初めて学ぶ概念の前提は省略しない。

### すべてのユーザー向け文章

問題文だけでなく、案内人のセリフ、メニュー、操作案内、ヒント、解説、フィードバック、エラー、権限不足、通信断、保存失敗、課金案内、確認テストの結果、復習への誘導まで、**子どもが見るすべての文章を教材品質管理の対象**とする。エラーでも専門用語を押し付けず、次にできる操作を示す。

## 4. つまずいたときの自立学習支援

1. まず自分で考え、解答する。
2. 難しければ**答えに直結しない段階的ヒント**を確認する。
3. 間違えたら、どこでつまずいたかに応じた基本解説を読む・見る。
4. わからなければ、より基礎的な説明や別の図・具体物・操作例へ進む。
5. 前提となる技能・単元が不足していれば、対応する学習へ戻る導線を示す。
6. 類題で理解を確かめ、自分で次の学習へ進む。
7. 理解を強制しない。休憩・あとで再挑戦・別の学習への移動も可能とする。

支援の各段階は**子どもが自分で選べ、迷わず戻れる**こと。保護者や先生の説明を前提にしない。課金の有無にかかわらず、基本的な理解に必要なヒント・解説は欠かさない。

### 試作版→β版での受け入れテスト例

- 幼児が読み上げ・絵・タップで問題の意味を理解し、迷っても自分で解き直せる。
- 初学者が誤答しても「不正解」だけで終わらず、次に何を見ればよいかを理解できる。
- 基本ヒントでわからない子が基礎的な図解・学習ページへ戻り、類題を自力で解ける。
- 通信エラーや未公開教材による「準備中」を表示する場合も、対処・戻り方を自分で選べる。
- 保護者が観察した「ここで大人に聞いた」場面を、後から改善課題として記録できる。

## 5. 管理者専用の教材レビューと公開ゲート

管理者画面は、対象問題について**問題／ヒント全段階／許容解答・別解／採点／基本解説／詳細解説／図やアニメーション／該当ステージと学習目標**を一括確認でき、子ども向けの実表示でもプレビューできること。

- 学年別の未習漢字検出、難しい語彙・長文・説明飛躍の警告（機械判定は候補提示であり自動確定としない）。
- 数学的正答の自動検算、別解条件検証、図・数直線・グラフの整合。
- ヒントが答えを早く伝えすぎる場合、途中の論理が抜ける場合の検出とAI改善案。
- 開発者による直接修正、修正前後の比較、テンプレート別・生成文別のレビュー。
- 「未確認／要修正／確認済み／公開準備完了／ボツ（廃止）」などの状態、ボツ理由、レビュー日時・承認者・内容の版・履歴の記録。
- 承認済みテンプレートの代表例・境界例・条件分岐・異なる描画ケースの確認。**生成した個別文章をテンプレート承認済みの代わりに自動承認しない**。
- **公開準備完了だけが配信対象**。状態を変更したら以後の配信に速やかに反映する。権限検証はサーバー側で行う。
- 10,400問/104,000問の登録件数、数学検証済み、文章レビュー済み、正式承認済み、公開可能数を別に集計する。

開発者の教育的な承認を経ないヒント・解説は公開しない。全件を手で読むことが困難な場合も、承認済みテンプレートの品質と実際に使われる内容の一致を確かめる仕組みを構築し、未承認の文を紛れ込ませない。

## 6. 全16島の正式構成と課金（後日確定仕様を維持）

旧引き継ぎ文書には「小1〜高3の12島＋賢者、通常/EX/隠し」と記されているが、これは**構想拡張以前の記述**。現行の正式構成は**幼児／小1〜高3の12学年／賢者／覇王／宇宙の16島**。

| 区分（正式な表示名） | 各島 | 全16島 |
| --- | ---: | ---: |
| **冒険の道** | 50ステージ | 800 |
| **確認テスト** | 10回（各5ステージ直後） | 160 |
| **試練の道** | 10ステージ | 160 |
| **伝説のトビラ** | 5ステージ | 80 |
| **問題バンクのあるステージ合計** | **65** | **1,040** |

確認テストは5ステージごとにマップの折り返しに置き、直前5ステージの審査済み問題から**毎回ランダムに重複なしの10問**を出す。確認テストを65ステージの内数にせず、教材目標へ二重計上しない。

- **β版の目標**：全16島×65ステージ×10問＝**10,400問**。全問題に正答、適切なヒント、基本・詳細解説、必要な図と品質審査が揃うこと。
- **最終目標**：全16島×65ステージ×100問＝**104,000問**。β版後の追加目標は93,600問。
- **既定の無料範囲（確定）**：小1〜高3の冒険の道600ステージ、単元別の基本学習ページと例題。無料でも子どもが自力で基本学習を続けられる基本ヒント・基本解説を用意する。
- **既定の有料範囲（確定）**：各学年の試練の道・伝説のトビラ、賢者の島、詳しい解説、弱点分析・苦手原因特定・克服問題・毎日15分の個別学習・定期復習・成長レポート。
- **追加の島の課金範囲（未確定）**：幼児の島の冒険の道無料・試練/伝説は有料、覇王・宇宙は全体有料、という案は既存の最上位仕様どおり**提案段階**。ユーザーの明示承認なしに本番の権限設定へ固定しない。
- **月額780円**は今回の引き継ぎ資料が示す**推奨案であり、正式料金未確定**。ユーザーが最終決定するまで固定しない。

**有料の詳細解説と無料の基本解説の境界**は教育理念によって審査する。理解に不可欠な説明を無料版から除外して親・先生の助けが必要な状態にしない。有料機能はより詳しい探究、個別化、継続支援などの上乗せとして設計する。

## 7. 試作品・限定β版・一般公開と目標時期

- **第一段階：試作品**。全16島の構造、代表的な問題形式、操作と採点・ヒント・解説・段階復習が通しで試せる。公開Pagesには安全なサンプル教材だけを用い、未審査教材や秘密情報を含めない。
- **第二段階：知人・子ども向け限定β版**。**全16島×65ステージに審査済み10問ずつ**、160確認テスト、地図・解放条件・基本学習・説明・安全な利用権・進捗保存・実機操作を満たしてから招待制公開する。
- **第三段階：一般公開**。βの改善結果を反映し、104,000問・本番向けの認証/決済/法務・個別支援・運用体制などを整備する。

**希望目標日**：β版 **2027年1月末**、正式公開 **2027年3月**。これはユーザーが提示した目標であり、**完成・品質審査・実機/安全性の条件より優先させない**。現時点で期日までの完成を保証しない。定期的に工程・残工数・品質状況を評価して更新する。

## 8. βテスター特典と評価

### 特典（導入希望の正式要件、実装未完了）

協力したβテスターには、正式公開後に**プレミアム2か月無料**で使えるユニークな特典コードを提供する。

- **1ユーザーにつき1コード**、**1回のみ有効**、**再使用不可**。
- アカウントに紐付け、同じ特典を不正に重複取得できないよう検証する。
- 特典コードから**自動課金は開始しない**。期間満了後に本人が別途加入しない限り課金しない。
- コード配布・交換・利用履歴・失効・期限・返金/契約との組合せをサーバー側で安全に管理し、未成年に意図しない決済をさせない。
- **βアクセス用の招待コードと正式公開後の2か月無料特典コードは目的・有効期限・利用権が異なるため別物**として扱う。前者は[β運用仕様](beta-operations.md)に従う。

### βテストの重点観察

- 子どもが大人の説明なしでゲームを始め、進められるか。
- 問題文・操作方法・エラー文言を理解できるか。
- 自分でヒントから気づけるか、誤答後の解説を読める・見られるか。
- 類題を自分で解き、次に何をするかわかるか。
- **どこで大人の助けが必要になったか**、その原因は言葉・図・操作・前提知識のどれか。
- おもしろさ・意欲・達成感・難易度・離脱・再挑戦の様子。

保護者は必要な範囲で観察し、子ども自身の操作・学習を代行しない。個人情報は最小限とし、学習ログ・回答ログ・識別情報の扱いは事前に同意と保護設計を検証する。

## 9. 実装と品質の優先順位

1. **子どもが自分で操作・理解・学習できること**。
2. **問題・ヒント・解答・解説の品質**。
3. **学年に合う日本語と直感的なUI**。
4. **つまずきの検出と自立して立ち直れる学習支援**。
5. **全学年・全島での単元網羅と適切な学習順**。
6. **ファンタジーRPGとしての楽しさ**。
7. **称号・収集・演出の継続要素**。
8. **プレミアム・収益化の最適化**。

ゲーム性・演出・開発効率・登録数を優先して、上位の学習品質を犠牲にしない。
