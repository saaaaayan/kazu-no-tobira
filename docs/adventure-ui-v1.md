# 数のトビラ — 冒険画面 v1 実装仕様（Codex用）

## 目的
現状の「たしざんの冒険」は、`src/App.tsx` のカード縦並びが中心。これを子どもが「次の場所へ冒険したい」と思える画面に改善する。ただし学習品質と3入力方式は最優先で保護する。

## 現状確認（元ブランチ codex/sequence-digit-recognition）
- Expo SDK 58 / React Native / Web / TypeScript。
- `src/domain/curriculum.ts`: 小1は `はじまりの森`、`月あかりの橋`、`星の塔` の3ステージ。他学年は `gradeIds` の定義のみでステージ未実装。
- `src/App.tsx`: 冒険マップが3つの `Pressable` カード。練習画面は問題バナー、3入力方式（keyboard/panel/handwriting）と `CalculationMemo`。
- `react-native-svg` は導入済み。認識ロジックを変更する必要はない。
- 手書きの実例（正解234/568をSVGで再現）は `tests/handwriting/` に登録済み。UI改修で認識パイプラインを触らないこと。

## 世界観・アートディレクション
- アプリ名は必ず **数のトビラ**。サブコピー候補「ひとつ解くたび、世界がひらく。」
- 柔らかく上品なファンタジー。ネイビー、青、薄紫、金の光、緑の森。暗すぎず、鮮やかすぎず。7歳児に読みやすい大きな文字・ボタン。
- 「教科書をカード化」ではなく、島の風景が見え、道が続き、次の目的地が見える**ゲームの冒険マップ**。
- 著作権侵害になる既存ゲームの素材・キャラクターを流用しない。追加ライブラリを増やさず、可能ならreact-native-svgによるオリジナルのベクター描画。
- 画面内で絵文字をそのまま大きく並べる手抜き表現は禁止。独自SVGと適切な文字レイヤーを使う。

## 第一段階: 冒険マップの実装
1. `src/components/AdventureMap.tsx` などに地図描画とタップ可能なステージ位置を分離する。データは `firstGradeStages` から取得し、ステージ名や進行状態を重複してハードコードしない。
2. 1つの「たしざんの島」全景を作る。森→月あかりの橋→星の塔へ曲がりくねった道でつながる。海、島の輪郭、木立、川、橋、山、塔、雲、星、光など、重なりのある風景で奥行きを出す。少なくとも現在地点、次の目的地、将来の目標地点が直感的に分かる。
3. ステージ地点はタップ・キーボード操作可能な明確なボタン。名前が読めるラベル、クリア済みはチェック印、次に進めるステージは光や枠、未解放は鍵と説明。色だけで状態を区別しない。
4. 未解放は解放まで起動できない。既存の `progress.stages` と `firstGradeStages` の順序から算出し、ステージ進行ルールは維持する。
5. `gradeIds` にある他11学年は世界の遠景として「これからの島」を示す場合でも、架空の学習ステージが実装済みのように見せない。操作可能なのは現在実装済みの内容だけ。
6. Web・スマホ・タブレットでマップとラベルがはみ出さない。狭い画面では縮小した文字を押し込むのではなく、地図の縦長表示・配置調整などで読める状態を保つ。
7. タップ領域は44〜48px以上を目安に確保。スクリーンリーダー用アクセシビリティラベルを設定する。

## 第二段階: 問題とクリア演出
1. 問題画面上部に現在の場所と全5問中の進行が分かるミニマップ/5つの星を配置。ただし既存問題・採点ロジックはそのまま。
2. 正解時には控えめな光・星の演出、ステージクリア時には大きな達成演出と「つぎの場所へ」導線。誤答時には責めないフィードバック。
3. 画面の見た目の改善で回答欄と計算メモが狭くならないよう、PC横並びとスマホ縦並びを再確認する。
4. 入力方式はキーボード・すうじパネル・手書きの3つを完全維持。**1つの手書き欄に複数桁を連続して書き、自動認識**、低信頼時のみ選択候補。
5. 子どもの誤操作を避けるため、派手な演出・移動アニメーション・音は控えめ。端末のReduce Motionを可能な範囲で尊重。音の自動再生なし。

## 品質基準（完了条件）
- 既存の学習問題・正誤判定・進行記録・保存を破壊しない。
- 3ステージとロック状態が正確に動き、解放後は次の地点が押せる。
- マップは縦に並んだ普通のカードUIのままではなく、一目で冒険世界と分かるグラフィカルな描画。
- 少なくとも320px前後のスマホ幅・一般的PC幅・タブレット幅の各レイアウトを確認。
- 日本語の表記・切れ・重なりがない。見出し/ボタンは十分なコントラストとサイズ。
- `pnpm test`, `pnpm typecheck`, `pnpm build:web` を実行。Webでステージ開始→入力方式切替→回答→クリア→次ステージの一連操作を検証。
- 検証していないAndroid/iOS実機・アニメーションについては未検証と記載する。
- `main` へのマージは禁止。実装は `codex/adventure-map-v1` にコミット＆プッシュ。
- 最後に変更ファイル、スクリーンショットまたはプレビュー、テスト結果、未完事項を報告。

## 実装上の注意
- 現行のコードでは `App.tsx` の `stageIcons=['🌲','🌙','✦']` と `styles.trail` / `styles.stage` がカードマップの本体。ここを置き換える。
- `HandwritingAnswer`、`recognition/`、`domain/addition.ts`、`grading.ts`、`progress.ts` のロジックは変更しない。
- 大幅なリファクタリングや新たなバックエンド導入は、この作業の範囲外。
