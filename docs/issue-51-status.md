# Issue #51 管理者認証と問題配信

## 検証した範囲

- 専用Supabaseに登録済みの管理者本人が、確認用PCでメール認証ログインに成功。起動済みの管理画面タブに4,323問が表示された。日をまたいだ検索では古いセッションが拒否され、ログイン画面へ戻った。
- 認証PR #57でHTTPS用Cookie、Originとホストの照合、管理者の有効状態とSupabaseセッションの照合、ログアウト時のセッション削除を実装した。一般ユーザー相当と未認証、別Origin、失効、ログアウト後の拒否は自動テストで確認した。
- 実DBの問題検索、詳細、審査更新、履歴、公開停止はロールバック付きのテストで確認した。4,323問は未確認のままで、公開準備完了は0問。
- DB出題を選ぶアプリは、冒険の道・試練の道・伝説のトビラ、試しプレイ、確認テスト、毎日学習、復習、診断、克服練習を共通APIに送る。公開配信は `ready` に限定し、発行したラウンドに含まれる問題だけをサーバーで採点する。ヒントは操作時に取得する。基本の解説は採点後、詳しい解説には利用権を要求する。
- 16島の冒険マップへ確認テストを10回ずつ配置した。問題候補は直前の実在する5ステージ。既存のステージ・問題IDを使用し、確認テストの成績は別枠に保存する。公開準備完了の候補が10問未満なら準備中。合格基準は仕様の決定後に追加する。

## 現在のアクセス先と残作業

- 管理者は [数のトビラ](https://saaaaayan.github.io/kazu-no-tobira/)のトップにある「管理者ログイン」を使用する。公開試作版のゲームは安全なサンプルのみで動く。正式教材の確認テストは公開準備完了の候補を使用する。
- 本番運用にはHTTPSのホスト、共通APIサーバー、購入権限を検証する実際のサービスを設定する。HTTPSサーバーは信頼するリバースプロキシからのみに接続を制限し、そこで `Host` を維持し、`X-Forwarded-Proto` と `X-Real-IP` を上書きする。別オリジンのゲームは `KAZU_GAME_WEB_ORIGIN` に正確なHTTPSオリジンを設定する。CORSの許可先は出題・ヒント・採点に限定される。
- 現在のサーバー設定は有料機能への要求を拒否する。購入が未接続なので、有料利用者の出題と共有環境への公開は保留。Android・iOSの実機、アプリ再起動後の途中再開、複数サーバーでのラウンド保存を検証する。端末の学習記録は既存形式を使う。
- Webの同じリリースモードで出力を測定した。旧設定は11,315,492バイト、DB専用は2,966,292バイト。8,349,200バイト削減し、問題JSONは43ファイルから0ファイルになった。
- 公開用エクスポートは `EXPO_PUBLIC_KAZU_GAME_ORIGIN` と `--production` を指定する。GitHub Pagesの既存の公開条件と品質ゲートに加え、`PRODUCTION_GAME_ORIGIN` の設定が必要。元の問題ファイルと復元用バックアップは保持する。
- Issue #52 の容量課題は旧版の完全復元を保てる保存方式を別に検証する。全104,000問の制作は [制作チェックポイント](question-production-checkpoint.json) から継続する。
