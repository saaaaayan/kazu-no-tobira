# 問題審査

[数のトビラ](https://saaaaayan.github.io/kazu-no-tobira/)のトップで「管理者ログイン」を選び、登録済みの管理者アカウントでログインします。認証と教材データは専用のSupabaseを使います。

1. 問題を検索して一覧から開きます。ゲームと同じ図・数式・解答操作で、問題・正答・ヒント・解説を確認できます。
2. 審査状態を選び、必要な理由とメモを入れて保存します。公開準備完了に進むには、現在の版を確認済みにし、教材の自動検査で残った指摘も解消してください。
3. 旧版との比較や操作履歴は問題の詳細で確認できます。検索・一括審査・CSVとJSONの出力にも、サーバー側で検証された管理者権限が必要です。

「学習目標と日本語の点検」は、登録・教材タグの明らかな不一致と、幼児〜小3の漢字・語彙・文の長さや説明の不足候補を表示します。[小学校学習指導要領の学年別漢字配当表](https://www.mext.go.jp/content/1413522_001.pdf)を使用し、小1の年度内の習得順は人が確認します。判定は審査の参考で、公開状態を自動変更しません。幼児の島50ステージの第1稿は、審査画面に「参考」として表示します。

専用Supabaseの詳細画面では「教材を編集」から問題文・操作案内・正答・3段階ヒント・解説を修正できます。差分と修正理由を確認して保存すると、旧版と審査履歴を残したまま、新しい版を未確認として登録します。公開準備完了だった版も出題対象から外れ、再審査が必要になります。競合する更新は上書きしません。履歴と教材の編集結果は専用DBに保存します。

## 幼児の島・第1ステージのモデル教材

管理者は `preschool.n01` の詳細で「モデル10問を通して試す」を開けます。図の個数を少ない順に確認でき、採点やヒントの操作は学習記録に保存されません。見て数える、タップして数える、数字を選ぶ、誤答後に番号付きの図を見るところまでを確認します。端末内の日本語音声が利用できるWebでは、問題・ヒント・基本解説を読み上げられます。

原稿はGit対象外の `question-drafts/` に保管します。専用DBの接続設定を有効にして、`node scripts/revise-preschool-model.mjs question-drafts/preschool-n01-model-review.json` で10問を検査し、DBの改訂と履歴の書き込みをロールバックします。実際に登録するときは `--apply` を指定します。対象10問の既存ID・版・審査状態が全件一致した場合のみ改訂できます。登録後は未確認のまま、人の教育審査を行います。公開試作版はサンプル専用です。

一般向けゲームで正式教材を配信するには、公開準備完了の審査と正式公開の条件が必要です。運用条件は [公開・検証フロー](release-process.md) を参照してください。
