# 問題審査の確認環境

正式な問題・審査データは専用Supabaseへ移行済みです。[DB接続の確認環境と再開手順](supabase-question-migration.md)を参照してください。以下は既存SQLiteを使うローカル確認用の手順です。

このWeb審査サーバーはPCの `127.0.0.1` にのみ接続を受け付けます。Node.js 24.11以降の `node:sqlite` を使い、ゲームのセーブと独立した専用ファイルに登録問題と審査履歴を保存します。ローカルの管理者キーは64桁のランダムな16進文字列で、Webに配信するディレクトリの外に初回起動時だけ生成します。

```powershell
pnpm exec expo export --platform web --dev --output-dir .expo/question-review-web
node scripts/start-question-review.mjs .expo/question-review-web 8123
```

1. [管理者ログイン](http://127.0.0.1:8123/admin) を開き、非公開の `.expo/question-review-private/admin-key.txt` にある管理者キーを入力します。
2. 問題を検索し、一覧から開きます。通常のゲームと同じ数式・図のコンポーネントで問題・解答・ヒント・解説を確認できます。
3. 審査状態を選び、ボツの場合は理由を選択して保存します。メモ・旧状態・新状態・審査日時・版を履歴に残します。公開準備完了には、現在の版を確認済みにしてから変更します。
4. 新しい問題バンクを取り込むには再起動します。制作中の教材はGit対象外の `question-drafts/` から取り込みます。公開リポジトリやWeb出力に原稿を含めると本文や正解を読めるため、その両方から外しています。同じ問題IDの内容が変わったときは、旧版とメモを保存し、状態を未確認に戻します。以前の版は問題の履歴から確認できます。レビューDBを他の端末に移す場合は、サーバーを停止してからDBファイルをバックアップしてください。

検索・一括審査・CSV/JSON出力にはサーバー側の管理者セッションが必要です。キーとDBはGitやWeb出力に含めません。Windowsで同じPCを複数人が使う場合は、管理者データの場所をその人専用のWindowsアカウント下に置きます。詳しい設定変更を行う前に [Node.js SQLiteの実装資料](https://nodejs.org/api/sqlite.html) を参照できます。

現在、公開準備完了だけに絞るサーバー内の選出関数は動作します。ゲームの通常出題・有料出題・毎日学習などはまだこのサーバーに接続していません。共有運用には管理者本人の認証、HTTPS、利用権のサーバー照合、全出題経路の切替、静的バンクの公開除外が必要です。本番の公開ゲートは維持します。
