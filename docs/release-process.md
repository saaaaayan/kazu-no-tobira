# 数のトビラ｜唯一の公開URL・運用と検証

> **ユーザーの最優先指定（2026-11-17）**：ゲーム、マップ、学習、管理者の操作先は **https://saaaaayan.github.io/kazu-no-tobira/** 一つだけ。ローカルプレビューURLや別ホストのUIを案内しない。決定事項は[AGENTS.md](../AGENTS.md)。

## 公開URLと管理者画面

- **唯一の入口**：https://saaaaayan.github.io/kazu-no-tobira/
- **管理者画面**：同じWebアプリ内の `/admin`。サイト内の管理者メニューから遷移し、ログイン済み・権限確認済みの開発者だけが審査・編集できる。
- GitHub Pagesは静的ホスティングなので、**認証・権限チェック・問題/解説の読書き・承認操作はサーバー側のAPI（Supabase等）**が必要。API内部のホストは実装技術であり、利用者向けのアクセス先ではない。
- 公開試作版で遊べるのはサンプル問題です。管理者はトップの「管理者ログイン」から入り、Supabase Auth と専用DBで権限確認を受けます。トークンはページ内のメモリに保持し、再読み込みには再ログインが必要です。
- **セキュリティ**：未承認教材・正答・管理者権限情報・認証秘密・編集APIの特権を静的成果物へ含めない。管理者画面のURLが推測されても、サーバーで認証・権限検証し、非管理者の閲覧・編集・CSVエクスポートを拒否する。
- 管理者APIは専用Supabaseプロジェクトの Edge Function `question-admin`。ゲートウェイのJWT検証に加え、各操作でAuthユーザー・セッション・管理者登録を照合します。DBは既存の `kazu_catalog_review` ロールで照会・更新します。Pagesのジョブは公開前にAPIの未認証拒否とオリジン制限を検査します。

## Codexが毎回行う手順

1. 正本はGitHub `saaaaayan/kazu-no-tobira` の `main`。既存の変更・DB記録・学習履歴を保護してPRを作る。
2. `pnpm test`、`pnpm typecheck`、`pnpm build:web` と、公開アセットへの未審査教材混入防止検査を実行。必須CI `verify` を通したPRのみマージする。
3. mainへのマージ後、`Publish 数のトビラ to GitHub Pages` を走らせる。既存の公開URL・配信設定・安全ゲートは維持する。
4. **公開HTTPから `/version.json` の `version` と `profile`、実際のHTML/JS資産を確認**し、公開SHAがmainの対象コミットに一致することを確認する。失敗なら失敗として報告し、安全に復旧する。
5. **同じ公開サイトの実画面**でPC/スマホのトップ→島→ステージ→問題→採点→解説→戻るを動作確認。管理者機能が統合できた段階ではログイン→権限確認→レビュー/編集→ログアウトと非管理者403を追加検証する。
6. 作業完了報告には**公開URL、完全なmain SHA、公開SHA、Actionsジョブ、実ブラウザー確認結果**を明示。公開未検証の場合は「公開完了」と呼ばない。

## 不要なローカル運用の廃止・クリーンアップ

- **利用者向け**のローカル確認URL、ローカル専用プレビュー、および管理者をそこへ誘導する手順を廃止する。
- **実行中のローカルサーバー、不要なビルド出力**は安全な移行を確認した時点で停止・クリーンアップする。個人PCのローカルファイルはGitHub操作だけでは削除できないため、**削除したと偽って報告しない**。
- **CIで必要な一時出力・テスト用の使い捨てディレクトリは別**。ビルド検証自体には一時的なファイルが不可避であるため、ユーザーに公開せずジョブ後に破棄する。
- **管理者APIをオンライン移行してから**ローカル専用起動スクリプトや重複プレビュー資産の参照を確認し、使われていないもののみ削除する。安全確認なしに教材の原本、ソース、依存ファイル、テスト、学習記録、DBを削除しない。
